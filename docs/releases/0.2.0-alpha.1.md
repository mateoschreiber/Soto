# Soto 0.2.0-alpha.1

Primera versión funcional alfa: configuración inicial protegida, bibliotecas locales montadas, catálogo persistente, reproducción con rangos y progreso, conversión multimedia en un worker separado, proveedores HTTP compatibles y descarga P2P en Rust.

## Instalación con Docker

Se publican dos imágenes Linux amd64 que deben usar la misma versión:

- API e interfaz: `ghcr.io/mateoschreiber/soto:0.2.0-alpha.1`.
- Worker con FFmpeg: `ghcr.io/mateoschreiber/soto:0.2.0-alpha.1-worker`.

Descarga `soto-compose.yaml` y crea una carpeta para tus medios. Configura `SOTO_LOCAL_PATH` con la ruta absoluta de esa carpeta y ejecuta:

```sh
SOTO_LOCAL_PATH=/ruta/absoluta/a/medios docker compose -f soto-compose.yaml up -d
docker compose -f soto-compose.yaml exec web /app/soto-server --print-setup-token
```

Abre [Soto local](http://127.0.0.1:3000), introduce el token mostrado por el comando y crea el administrador. El token solo se utiliza para la configuración inicial. Añade una biblioteca de la raíz local y ejecuta el escaneo desde la interfaz. Los archivos locales se montan de solo lectura.

La API escucha en la interfaz de loopback del host de forma predeterminada. El worker no publica puertos y utiliza un secreto interno compartido. Para acceso desde otros equipos, configura un proxy HTTPS y `SOTO_PUBLIC_URL` antes de publicar el servicio.

## Instalación portátil

El archivo `soto-0.2.0-alpha.1-linux-amd64.tar.gz` contiene **ambas imágenes**. Comprueba `SHA256SUMS` y cárgalas sin recompilar:

```sh
sha256sum -c SHA256SUMS
gzip -dc soto-0.2.0-alpha.1-linux-amd64.tar.gz | docker load
SOTO_LOCAL_PATH=/ruta/absoluta/a/medios docker compose -f soto-compose.yaml up -d
```

Los volúmenes `data`, `control`, `torrents` y `cache` conservan configuración, secreto interno, descargas y conversiones. Conserva una copia de seguridad de `data` y no elimines los volúmenes al actualizar. Esta alfa funcional utiliza almacenamiento nuevo; la demostración 0.1 y sus recursos publicados se conservan, sin migración automática de datos de demostración.

## Alcance y comprobaciones

La publicación exige construir y comprobar las dos imágenes juntas mediante una instalación limpia: token inicial obtenido por CLI, autorización, escaneo de un video generado con FFmpeg, lectura real de rangos, persistencia de progreso después de reiniciar, conversión a HLS fMP4 y comprobación de salud de ambos procesos. El video de prueba contiene patrones y audio sintéticos; no utiliza cuentas externas ni contenido protegido.

La conversión se limita a una tarea multimedia simultánea. Las cuotas y los límites P2P se configuran desde Ajustes; P2P comienza deshabilitado. Las fuentes remotas requieren disponibilidad del proveedor y las conversiones por flujo no admiten búsqueda arbitraria. No se garantiza compatibilidad con todos los contenedores, códecs, proveedores ni diseños MP4 que requieren búsqueda en la entrada. Las conexiones externas y las cuentas Real-Debrid deben configurarse y comprobarse con credenciales propias.

Esta es una versión alfa para evaluación en homelab. No incluye APK.
